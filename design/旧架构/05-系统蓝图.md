# 05 系统蓝图

日期：2026-09-23
前一步：[04-模块边界.md](04-模块边界.md)

网页负责按顺序调用模块。模块之间不互相调用，也不改对方的账。要看别人的结果，只能读。

## 平时提问

用户上传 PDF 并提问时，网页按这个顺序调用：

1. 文档。保存 PDF，抽出正文，记下 token 数和有没有超过窗口的 80%。
2. 切块。只在没超过上限、并且至少一份文档抽出了正文时调用。
3. 提问。记下这个问题。
4. 选文。默认用 Jev。选文调用 Jev，留下必要的块。
5. 作答。调用 DeepSeek-V4.1-Flash，只把问题和选文留下的块送进去。

选文先校验文档集、问题和切块版本，再执行策略。没有块达到规则时可以得到“空结果”；默认不调用生成模型并返回不可形成证据的状态。

任何一步失败，后面的步骤不调用，也不补记空账。选文失败，就没有作答。作答失败，选文保留。

同一批 PDF 再问新问题时，文档和切块不再调用。网页只调用提问、选文和作答。

## 事实落在哪

| 事实 | 记在 |
| --- | --- |
| PDF、抽出的正文、token 数、是否超限 | 文档 |
| 块的文本、顺序、token 数、切分规则版本 | 切块 |
| 问题原文；QASPER 题的参考答案和证据位置 | 提问 |
| 留下哪些块、每块分数、筛选费用和耗时 | 选文 |
| 回答、生成模型的 token、费用和耗时 | 作答 |
| 三次回答的词重合分、费用和延迟汇总、无效标记 | 证明 |

页面上“少送了多少文本”不另记一笔。它由网页读切块的总 token 和作答送入的 token 后算出来。

## 外部服务只有两处入口

- Jev、Embedding 模型和 Cross-Encoder 只由选文调用。整篇选法不调用外部服务。
- DeepSeek 只由作答调用。

提问、切块、文档和证明都不直接调用这些服务。

## 证明时谁调用谁

证明 QASPER 时，由证明模块代替人手，调用和网页相同的顺序。一篇论文只调用一次文档和切块。这篇论文有多道题时，后面每道题只调用提问，再对同一批块调用三次选文、三次作答。

三次选文分别是整篇、Jev、标准检索。标准检索由选文去调用现成的 Embedding 模型和 Cross-Encoder。三次作答各自只读自己的那一份选文。

算完分数后，证明只把汇总写进自己的对比记录。某一次文件、切块或提示不一致，证明把它标成无效，不回头改那一次的选文或作答。

## 失败和复现

- 文档处理失败或文档集超限：问题不创建，选文和作答不调用。
- 切块失败或块版本不可用：选文失败，不产生作答。
- 选择服务失败或只完成部分块评分：选文保留失败/部分完成状态和已发生的费用，作答不调用；重试必须产生新的选文记录。
- 作答失败：选文不变，作答记录为失败；重试产生新的作答记录。
- 每份作答只能引用一份未作废选文。复现必须固定正文版本、切块版本、问题原文、策略版本、模型标识和提示版本。

## 实验台生命周期与证明接口

网页支持显式重切、选文重试和作答重试；重切后旧选文仍能查看，但输入有效性为 `obsolete`，不能继续生成。作答历史按创建顺序保存，运行响应的兼容字段 `answer` 指向最新作答，同时 `answers` 暴露全部历史。

证明服务只读问题、工作区、选文和作答，创建独立比较快照：`POST /questions/{question_id}/comparisons`、`GET /questions/{question_id}/comparisons`、`GET /comparisons/{comparison_id}`。比较快照保存正文近似量、完整块上下文、选中上下文、同口径节省率、usage 来源、阶段耗时、费用状态和 `not_run` 评分状态；模式缺失或输入失效时标为 `incomplete`，不调用模型。
