# 24 模块设计：切块

日期：2026-10-05

前一步：[23-模块-文档.md](23-模块-文档.md)

这一份只定合同审查里的切块。旧规则留在 [16-模块-切块.md](16-模块-切块.md)。切法不变，变的是它从按页完成的文档记录里取内容，并且切块任务也能单独恢复。代码还没改。

## 这个模块做什么

读取文档模块已经完成的页面，把文字、表格和图片切成后面可以检索的块。它不重新识别 PDF，不决定风险项，也不调用 bge、Jev 或 DeepSeek。

一批里还有页面失败时，不开始切块。

## 沿用的切法

- 文字：同一标题下的段落。过短才合并，合并后不超过上限，块首保留标题。
- 表格：一整张 Markdown 表单独成块。超过上限时按行切开，每一块重复表头，不从一行中间切开。
- 图片：一张图一块，不切开。识别出的文字或表格跟着这块保存，原图也跟着这块保存。
- 一块最多 512 个 token，不重叠。页眉和页脚不进入块。

没有安装 Docling 时，用本地的同样规则，不另造一种切法。

## 一块记下什么

编号、所属文件、顺序、种类、用来检索的文字、token 数、原图和切分规则版本。

来源必须能回到文档模块的页面记录：

| 来源 | 含义 |
| --- | --- |
| 文件 | 文档编号和上传时的文件名 |
| 页 | 文档页记录的编号和 PDF 页码。跨页时两页都记 |
| 位置 | 这一页里第几段、第几张表或第几张图 |
| 标题 | 这一块上面的各级标题。没有就为空 |

这些来源只从文档模块已经保存的页码和阅读顺序复制，不从页眉猜测。

## 恢复

切块的最小单位是一页。工作进程一次领取一页已完成的文档页，先写成处理中并提交，再产生这一页的块。

同一页重新领取时，先看这一页的块是否已经完整。完整就保持原块和原编号，不新增第二套。不完整就删掉这一页未完成的块，再用同一个页面记录重新切。

工作进程退出时，处理中的切块页改回等待。已经切完的页不重切。文档页后来重试并得到新内容时，只把这一页标成等待重切，其他页的块保持不变。

## 什么时候整批重切

加一份或删一份文件，只处理这一份。只有 512 token、不重叠或三类块的规则变了，才把当前还在的文件全部重切。旧块保留，但新审查不能再读旧块。
