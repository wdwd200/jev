# 20 上线前要做的事

日期：2026-10-02

这份只在项目要放到简历上、给别人打开时再看。它不是模块设计，也不授权现在就租服务器或改代码。

## 先分清两种对外

**本机对外。** 程序仍跑在自己的电脑上，不租服务器。地址不是 `127.0.0.1`，同一网络里的手机或其他电脑能打开。这就是之前做过的调试。它能检查上传、页面和本机到模型接口的调用。

它不能写进简历。电脑关机、睡眠或离开当前网络，网址就打不开。家庭网络的地址也会变。

**租一台服务器。** 程序一天到晚跑在别人机房的机器上，有一个固定地址。简历上的网址要用这一种。

## 什么配置

旁边的 `runtime` 是一个 Python 网页服务，模型调用走外部接口，不在机器上加载大模型。本项目的展示版也一样。两个都不必上 4 核 8G。

更便宜的做法是租两台 2 核 2G，各跑一个项目。按上面的公开价，两台一年 918 元，比一台 4 核 8G 的 2346 元少。一台崩溃也不影响另一台，密钥和数据库本来就要分开。简历可以放两个网址。

两个项目先挤在一台机器上，用 2 核 4G，一年 1020 元。内存仍然分开算，不能把检索模型常驻进去。本项目以后要在机器上常驻 `bge-m3` 和重排模型，再单独把这一台升到 4 核 8G，不提前为两个项目都付这一档。

| 配置 | 用途 |
| --- | --- |
| 2 核、4G 内存 | 只够本项目的网页、SQLite、PDF 解析和外部接口。不在机器上加载检索模型，也不够再跑另一个项目。 |
| 4 核、8G 内存 | 本项目加上另一个轻量网页项目。本项目的 `bge-m3` 和重排模型先不要常驻内存。 |
| 4 核、16G 内存 | 两个项目同时跑，并且本项目要在这台机器上做向量检索。检索模型单独就要数 G 内存。 |
| 带宽 | 3M 到 5M 够两个普通页面和一份 PDF 上传。两个项目都频繁传大文件时再加大。 |
| 系统盘 | 60G 起。两个项目的依赖、PDF 和模型文件分开存放。 |

DeepSeek 和 Jev 的计算不在这台机器上。机器必须访问得到这两个接口。另一个项目如果自己要在本机跑模型，按那个模型的内存另加，不使用上面的档。

两个项目各用各的目录、端口、密钥和数据库。前面用一个网站入口按域名或路径转发。一个项目崩溃，不能把另一个一起停掉。

## 租完还要做的

租机器不等于已经上线。

1. 装两个项目的依赖，各自设成开机自启。一个崩溃只重启它自己。
2. 有一个不变的地址。只有 IP 也能用，但 IP 一变简历就失效，所以最好有域名。
3. 配置 HTTPS。没有证书时，浏览器上传会提示不安全。
4. 密钥只放在服务器上，不进页面、仓库和报错。
5. 公网只留一个页面：上传 PDF、提问、看答案，以及原文多少 token、这次送进多少、少送了多少。实验接口和数据库不能从公网打开。
6. 限制单份 PDF 的大小、页数和请求超时，避免一份文件占满磁盘。
7. 首页不写“优于检索”或“知识库”。全文和 Jev 并列。检索只在 Jev 不可用时使用，不放在首页当结论。

第一版不做账号，数据库继续用这台机器上的 SQLite，不另租数据库。

## 本机对外还能调试什么

还能用来看页面和上传。它看不出这三件事：机房里能不能连上两个模型接口、公网上传会不会超时、电脑关机后网址还在不在。这三件要等租了服务器再看。

本机对外和租服务器，都不代替本地把文档、切块、提问、选文、作答和证明按设计改完。
