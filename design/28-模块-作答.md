# 28 模块设计：作答

日期：2026-10-06

前一步：[27-模块-审查.md](27-模块-审查.md)

这一份只定合同审查里的作答。旧问答规则留在 [18-模块-作答.md](18-模块-作答.md)。代码还没改。

## 这个模块做什么

读取一项已经停止的审查，把结论、引用的块和页码写成用户能看的说明。它不重新检索，不把找到改成冲突或缺失，也不计算准确率。

生成模型仍是 DeepSeek-V4.1-Flash，接口名 `deepseek-flash`。思考关闭。调用继续走 HTTP 接口。

## 什么能作答

只有状态为完成、并且结论是找到、冲突或缺失的审查可以作答。检索失败留下的审查不调用模型，页面显示这项没有完成。

一项审查只对应一次当前作答。作答失败不修改审查。再试一次只新建一条作答，仍读原来的结论和原来引用的块。

## 送进去什么

送入风险项名称、原问法、最终结论、每一块的文字和页码。文字块送带标题的文字，表格块送 Markdown 表格，图片块送识别出的文字。

原图先不送。DeepSeek 当前接口能不能接收图片仍未从官方说明确认。确认前，原图留在块上，作答记录里标明图片没有送出。

提示要求说明三件事：结论、支撑这个结论的页码、不能从引用内容推出的部分。提示里不出现重排、Jev 或模型名称。模型不能补充引用里没有的条款。

## 记下什么

编号、用的哪一项审查、模型名、提示版本、说明原文、输入 token、输出 token、费用、耗时、失败原因、图片是否送出。

输入和输出 token 以接口返回为准。接口没有返回时，用 DeepSeek 公布的分词器估算，并标明是估算。没有价格表时费用保持未计算，不填 0。

## 恢复

作答是一项审查上的一个阶段。工作进程先写成处理中并提交，再调用 DeepSeek。调用期间不占着数据库事务。

重新领取时，已经成功的作答保持原编号和原文。处理中但没有写完的作答，沿用原编号重新调用，不留下两条处理中的记录。密钥和接口地址不能进入失败原因。
