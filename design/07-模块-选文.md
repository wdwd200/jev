# 07 模块设计：选文

日期：2026-09-30
前一步：[17-模块-提问.md](17-模块-提问.md)

只设计选文模块。它不改文档、不切块、不改问题，也不调用生成模型作答。

2026-09-30 起，这一份是选文的现行规则。同日之前写在这里的实验台行为不再有效。2026-10-02 起，全文、Jev 和标准检索按这一份分开走。Jev 的门槛和预算仍然没有定。

## 这个模块做什么

读取一句已经定下来的问题，从这次对话里还留着的块中，决定哪些块值得送给生成模型。一次选择留下一份不再改动的选文记录。

整篇、Jev、标准检索是同一本账里的三种记法，不是三个模块。三路使用同一句问题、同一套还在的块。题库题用原文。用户自己的追问用改写后的那一句。

选文不判断答案对不对，也不宣称留下的块已经足够回答。

## 参考的现成做法

标准检索只借鉴“先向量召回，再交叉编码重排”，不接入别人的整套问答。

| 来源 | 做法 |
| --- | --- |
| FlagEmbedding | 先用向量模型召回一批，再用 `bge-reranker` 对这批重新排序。说明里没有规定召回多少、留下多少。 |
| `bge-reranker-v2-m3` | 直接给“问题，块”打分，分数越高越相关，可以用 sigmoid 映到 0 到 1。它自己的评测是把向量检索的前 100 条拿来重排，其中包括 `bge-m3`。模型卡没有规定上线时留几条，也没有规定分数门槛。 |
| 本项目已写在 `15` 的协议 | `bge-m3` 召回 20 块，`bge-reranker-v2-m3` 留下 5 块。这是本项目的实验数字，不是上述模型的默认值。 |

`15` 里同时写过 256 个 token、重叠 32。切块规则已经改成一块最多 512、不重叠，那两个数不再用于切块。召回 20、留下 5 仍然有效。

Jev 没有对应的开源检索默认值。它是逐块做一个带概率的是否判断，所以用门槛，不用“固定留下几块”。

## 技术选型

Jev 用 TypeSafe 的判别接口，模型名沿用 `jev-latest`。它只做带概率的是否判断，不生成答案。没有第二个判别模型要选。

标准检索的向量和重排用 `BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3`，通过 sentence-transformers 在本机计算。这是已经写进实验协议的组合。`bge-m3` 还能做稀疏和 multi-vector，第一版只用稠密向量。不接入 Elasticsearch、Pyserini 或一整套知识库。倒排索引和 BM25 留到上线之后。

调用方式继续用现在的 HTTP 请求，不换框架。

## 三种选法

候选块只来自这次对话里还没删除的 PDF。文字块读带标题的文字，表格块读 Markdown 表格，图片块读图注和图表说明。选文不看图片像素。图片一旦被留下，原图仍挂在这块上，交给作答。

### 整篇

留下全部当前块。不调用 Jev，也不调用检索。选择费用为 0。当前没有块时是空结果，不作答。

### Jev

对每一块结合这句问题做一次判断，得到“值得送入”的概率。达到门槛的留下，再按证据 token 上限裁剪。没达到门槛的不留下。一块都没达到时是空结果，不偷偷保留最高分的一块。

某一块调用失败，不能当成低分。有块没评完时是部分完成，不作答。服务整体失败就停止，不改走整篇或标准检索。

门槛和证据 token 上限还没有定。代码里现在是 0.5 和 6000，试跑用过 1200。这些都不是这一份已经定下的规则。定下来之前不把它们写进分数。

### 标准检索

用 `bge-m3` 给问题和每一块做向量，按相似度召回 20 块。再用 `bge-reranker-v2-m3` 对这 20 块打分，留下 5 块。两个模型都不训练，也不生成答案。

这里用固定条数，因为这个重排模型没有规定分数门槛。当前块不足 20 或不足 5 时，有多少留多少。检索或重排失败就记下失败，不改走整篇或 Jev。

## 一份选文记下什么

编号、属于哪个问题、用的是原文还是改写句、选法、所读的块来自哪些还在的 PDF、每一块的分数、留下的块、每一块的来源、状态、失败原因、选择本身的 token、费用和耗时。

状态有：完成、部分完成、空结果、失败、已作废。空结果不是失败。部分完成和失败都不进入作答。

选文创建后不改块列表。再选一次就新建一份。删除 PDF 只影响之后的新选择。已经留下的选文保留当时复制下来的文字、表格、图片和来源。

## 产品里的位置（2026-10-02）

全文和 Jev 并列，给用户选。标准检索不再作为首页上要打败的对照，而是 Jev 不可用时的降级。

这个取舍来自使用成本。Jev 逐块判断，目的是少送输入 token。用户有时要绝对稳妥，愿意放弃省钱，这时直接读全文。Jev 服务失败、超时或只评完一部分时，不把失败伪装成成功，也不自动改成全文，因为全文是用户显式选择的另一条路。这时才用标准检索留下有限的块，让这一问还能作答。

题库比较不受这个取舍影响。证明 Jev 和衡量我们自己的检索时，三路仍在同一批块上各跑一次。降级只发生在用户真实提问、并且 Jev 不可用的时候。

## 标准检索的两档

现在先用简单的一档，保证能上线：`bge-m3` 的稠密向量召回 20 块，`bge-reranker-v2-m3` 留下 5 块。不建倒排索引，也不做关键词检索。

以后再做的一档，记录在这里，现在不接入：

| 做法 | 是什么 | 现在为什么不做 |
| --- | --- | --- |
| 倒排索引 | 每个词指向出现过它的块。按词查找，不用把每块都重算一遍向量。 | 这一批 PDF 最多约 80 万 token，块数不大，先算向量就够。 |
| BM25 | Elasticsearch 和 Lucene 的默认打分。按词在这块里出现多少、在整批里稀有程度、以及块的长度打分。 | 要先有分词和倒排索引。上线后再加。 |
| 稀疏检索 | `bge-m3` 除了稠密向量，还能给词项打权重，官方说明称为 dense、sparse、multi-vector 三种能力。 | 和稠密向量是同一个模型，但要另接一套权重和索引。 |
| 混合 | 把 BM25 或稀疏检索的结果，和稠密向量的结果合在一起，再重排。 | 依赖上面几项。现在用单一稠密召回。 |

改进时仍使用同一套块和同一个生成模型。不改接一整套知识库产品。

## 代码做到哪了

全文和 Jev 是并列选择。标准检索默认关闭。只有明确打开，并且 Jev 没有完成时，才改走标准检索。空选文仍然是一次完成的选择，不改走检索，也不改走全文。

选文只读当前还在的块，并复制块的种类、来源和有没有原图。倒排索引、BM25、稀疏检索和混合检索还没做，仍按上面的表留到上线以后。
