# 23 模块设计：文档

日期：2026-10-05

前一步：[22-单体模块架构.md](22-单体模块架构.md)

这一份只定合同审查里的文档模块。旧问答实验台的规则留在 [06-模块-文档.md](06-模块-文档.md)。代码还没改。

## 这个模块做什么

一次审查里上传的 PDF 属于同一批。文档模块保存原文件，识别每一页里的文字、表格、图片和扫描内容，并给每一页留下可单独重试的记录。

它不切块，不决定风险项，不调用 bge、Jev 或 DeepSeek 作答。Word 以后也要变成同样的文字、表格和图片，这一版不接。

## 一批合同

一批是这一次审查要一起阅读的 PDF。一份也算一批。

| 字段 | 含义 |
| --- | --- |
| 编号 | 这一批的编号，之后不变 |
| 建立时间 | 批次建立的时间 |
| 状态 | 等待、处理中、可继续、已拒绝 |
| 正文 token 合计 | 已完成页面里，文字、表格文本和图片识别文本的总和 |
| 上限 | 生成模型上下文的 80%，当前是 80 万 token |
| 拒绝原因 | 只有已拒绝时才有 |

网页只创建批次并返回编号。工作进程负责改状态。超过 20MB、100 页或 80 万 token 时，只把这一批写成已拒绝，不删除已经识别完的页面。

## 一页一条记录

页是重试和恢复的最小单位。每一页保存：

| 字段 | 含义 |
| --- | --- |
| 编号 | 这一页的编号 |
| 所属文件 | 它来自哪份 PDF |
| 页码 | PDF 里的页码，从 1 开始 |
| 状态 | 等待、处理中、完成、失败 |
| 内容 | 按阅读顺序保存的文字、表格和图片 |
| 失败原因 | 只有失败时才有 |
| 尝试次数 | 这一页已经开始过几次 |

表格保存成一整张 Markdown 表，不压成一行。图片保存原图；扫描页、图表和没有文字层的图片，还要保存识别出的文字或表格。识别只服务后面挑选，不替代原图。

重复出现的页眉和页脚不进入可挑选内容。页码和文件名记在来源里，原 PDF 保留。

## 阶段和重试

一份 PDF 先只建立页面记录，不在建立时识别。工作进程一次只领取一页，先把状态改成处理中并提交，再做识别。识别期间不占着数据库事务。

一页失败只把这一页改成失败。同一份 PDF 里已经完成的页面保持完成。再次领取时使用原来的页面编号，不新建第二条页面。

已经完成的页面不能因为文件重试而被重新识别。工作进程退出后，状态仍是处理中的页面改回等待；下次从等待页继续，不重做完成页。

## 网页能看见什么

网页按批次编号读取状态、总页数、完成页数、失败页数和拒绝原因。它可以显示哪一页失败，但不能读取密钥、数据库路径或外部调用的原始报错。

文档状态不是审查结论。页面全部完成只表示可以交给切块；某一页失败时，已完成页面仍保留，但这一批不能进入切块。
