# 17 模块设计：提问

日期：2026-09-30
前一步：[16-模块-切块.md](16-模块-切块.md)

只设计提问模块。它不切块，不决定留哪些块，不调用 Jev，也不计算分数。

这一份是现行规则。2026-10-02 起，代码按这一份改写用户追问，题库题保持原文。

## 这个模块做什么

把用户在一次对话里提出的问题记下来。从第二句开始，把依赖上文的说法改写成一句可以单独拿去选块的话。整篇、标准检索和 Jev 都用这句改写，不各自再改一次。

题库里的题不改写。那些题用来衡量 Jev 有没有效，以及本项目自己的标准检索有多准。改写不是那次分数的一部分。

## 参考的现成做法

多轮追问的成熟做法，是把省略和指代补成一句独立的问题，再用这句去检索。

| 来源 | 做法 |
| --- | --- |
| CONQRR | 把依赖上文的问题改成自包含的问题，再用检索效果训练改写器。改写器不回答问题。 |
| LlamaIndex `condense_question` | 每一句先按对话历史改写，再用改写后的句子检索。它总会去查资料。 |
| QReCC | 1.4 万段对话、8 万个问答，用来同时看改写、检索和回答。论文基线的答案 F1 是 19.10，人工上限是 75.45。那是网页检索，不是这批 PDF，不能当作本项目的及格线。 |

Query2doc 和 HyDE 是给单句补一段假想文字，不解决“那它后来呢”，不采用。

本模块只借用“追问改成一句独立问题”这一步。不训练改写器，不用 QReCC 的 19.10 当目标分。

## 技术选型

改写调用同一个 DeepSeek-V4.1-Flash，接口名 `deepseek-flash`，关闭思考。不另接一个改写服务，也不训练 CONQRR 那种用检索奖励训练的改写器。题库题数量有限，单独训练一个模型的成本盖过收益。

LlamaIndex 的 `condense_question` 只说明步骤：用历史把追问补成独立问题，再用这句去选块。不把它的库接进来。QReCC 只提供对照方法，不提供要接入的服务。

## 用户自己的问题

一个问题属于一次对话。记下编号、用户原文、提出时间、改写后的句子、改写状态。原文创建后不改。

第一问没有上文，改写结果等于原文，不调用模型。

从第二问起，把这次对话里前面的问题和答案交给 DeepSeek，生成一句独立的问题。关闭思考。这句话只补代词和省略，不回答，不加入对话里没有的事实。

改写失败时，三路都退回原文，并在问题上记下退回。不允许一路用改写、另一路用原文。

改写花掉的输入 token、输出 token 和费用记在问题上，不记进某一路选文。

这一批是已拒绝，或者问题是空白，就不创建。

## 题库里的题

题库题本身是完整问题。没有对话上文，也不做改写，避免把标准题改成另一句。

同一题、同一套块，分别用整篇、本项目的标准检索和 Jev 各跑一次。分数用来看 Jev 本身，也用来看这套检索本身。不把改写算进这次比较。

## 和文档变化的关系

用户在下一问之前添加或删除了 PDF，这一问用改写后的句子，从当前还在的块里重新选。上一问仍然指向它当时的选文。

上一问的选中块不带进这一问。

## 代码做到哪了

第一问和题库题不调用模型。用户追问会改写成独立问题，原文另存。改写失败时三路都用原文，并在问题上记下失败。选文和作答读改写后的句子。
