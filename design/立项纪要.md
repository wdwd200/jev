# Jev Context Selector 立项纪要

日期：2026-09-23
状态：立项讨论已收敛，实验协议尚未冻结

## 1. 背景

面向有限规模的私有 PDF 问答。用户在网页端上传 PDF，系统限制单个工作区的文档总量，使抽取后的正文始终能放进生成模型的上下文。

在这种规模下，传统检索加排序不一定划算。本项目要验证：让判别模型 Jev 直接判断每个文档块对当前问题是否必要，再把选中的证据交给生成模型，能否在答案质量接近“整篇阅读”和“标准检索”的同时，省掉 Embedding 召回和 Cross-Encoder 重排。

Jev 是 TypeSafe AI 的判别模型。它不生成正文，一次前向输出带概率的判断。本项目里它只筛选证据，不回答用户。

## 2. 目标

在同一数据集、同一套切块、同一个生成模型和同一套作答提示下，只改变上下文怎么选，比较三种方案，并报告答案质量、输入 token、总成本和响应延迟。

| 方案 | 做法 |
| --- | --- |
| A Full Context | 工作区全文交给生成模型 |
| C 标准 RAG | Embedding 召回，再经 Cross-Encoder 重排，然后交给生成模型 |
| D Jev 直选 | 同一套切块后，由 Jev 逐块判断是否必要，选出证据再交给生成模型 |

没有方案 B。这是明确不做，不是漏项。

## 3. 范围

做：

- PDF 解析，以及三边共用的一套确定性切块。
- A、C、D 三条可切换的问答链路。
- 网页实验台。用户上传一批 PDF 再提问，这一批就是一个工作区，一份或多份都可以。抽出的正文总量有上限。
- 在公开 Benchmark 上出对比结果。

不做：

- 训练或微调 Jev。
- 更换或对比多个生成模型。
- 非 PDF 文档。
- 多租户、权限、计费产品化。
- 生产级增量索引。
- 低置信度时再升级给生成模型做二次判断。低置信度只记录比例。

网页允许一次上传多份 PDF。QASPER 打分时，一道题只上传它对应的那一篇，因为这道题只考这一篇。一次上传多篇再提问可以正常使用，只是这套题没有这种考法，不算进这次的分数。

## 4. 已定选择

- Benchmark：QASPER。约 5049 道题、1585 篇 NLP 论文。提问人只看标题和摘要，答题人阅读全文并标出证据。
- 生成模型：DeepSeek-V4.1-Flash。API 模型名为 `deepseek-flash`。上下文长度 100 万 token。
- 工作区上限：抽取后的正文不超过上下文窗口的 80%，即约 80 万 token。超过则该次作废，不参与对比。QASPER 单篇远小于这个上限，上限是为了保证方案 A 不被截断。
- 主评测只保留能从正文回答的题，沿用 QASPER 论文的做法，排除必须以图或表作证据的题。

## 5. 公平性约束

1. 三边使用同一份 PDF 解析结果。解析失败是共同失败，不记成某个方案的输赢。
2. C 和 D 使用同一套切块：按 token 窗口切，带固定重叠。不用语义切块。具体窗口和重叠在实验协议冻结前写死，立项不先定数字。
3. 三边使用同一个生成模型、同一次价格表、同一套作答提示。提示里不出现方案名称。
4. 生成调用关闭 thinking。QASPER 的答案很短，思考模式会拉高 token、延迟，并让回答变长。
5. 作答提示要求短答案：原文短语、Yes、No 或 Unanswerable。不写解释。否则多出来的词会被扣分，比的就不是答案对不对。

## 6. 成功标准

主指标是 QASPER 的 Answer-F1，记为 0 到 100 分。它不是老师打的印象分，也不是答对题数的百分比。做法是把模型回答和参考答案拆成词，看重合程度。一题有多个参考答案时取最高分。全部测试题再取平均。

QASPER 不是一题一句标准答案。44% 的题有多个标注。答案多数是从论文里摘出的短语，摘录答案平均约 14.4 个词，概括答案平均约 15.6 个词。也有 Yes、No 和 Unanswerable。

暂定及格线：

- D 的 Answer-F1 比 A 低不超过 3 分。
- D 的 Answer-F1 比 C 低不超过 3 分。

这 3 分是全部测试题的平均分，不是每一题允许差 3 分。它可以改。改动必须发生在查看测试集结果之前，并记入实验协议。看完结果再改，这条线作废。

证据选得准不准另报 Evidence-F1，只用来区分“选错了块”和“选对了但生成模型答错了”。它不决定过不过。

成本和延迟只报告，不作为本次是否立项成功的门槛。成本口径是同一次运行的实际账单：生成模型的输入和输出，加上选择阶段的费用。A 的选择费用为 0，C 计入 Embedding 与 Reranker，D 计入 Jev。延迟同时报告选择阶段和端到端的 p50、p95，不用平均值代替。

## 7. 方案 D 的可操作定义

v1 不追求数学意义上的最小证据集。最小集通常要逐块试探边际收益，调用无法并行。

v1 定义为：Jev 用是否判断（noul）给每个块一个“对当前问题是否必要”的概率。概率不低于阈值 τ 的块进入证据，并设选中证据的 token 上限。没有块达到阈值时允许空结果，不伪造证据；如验证阶段需要“至少一块”的兜底，必须成为单独的策略版本。τ 在开发集上确定，确定后固定，再跑测试集。

## 8. 风险

1. Jev 宣传中的低延迟，依赖一份长上下文只做一次前缀计算、再并行问很多短问题。本项目是每个块内容不同、问题相同。前缀共享用不上，延迟和费用必须以实测为准。
2. 方案 C 的 Cross-Encoder 是专门做段落相关性的模型。Jev 没有思维链，选项顺序和无关选项都会影响概率。逐块问“是否必要”可能弱于重排器。负结果是有效结论。
3. Jev 的概率校准不一定迁移到“这一块是否必要”。很多块只是部分相关。
4. 如果生成模型写成段落，Answer-F1 会被多余的词拉低。短答案约束必须先在开发集上检查。
5. QASPER 只覆盖单篇 NLP 论文，不能外推到多文档工作区、扫描版 PDF 或图表问答。

## 9. 三套方案怎么共用 QASPER

网页平时只有两种用法：不用 Jev、整篇送给 DeepSeek，这是 A；用 Jev 选段落，这是 D。C 不是网页本来就有的功能，也不是我们新发明的选文方法。C 是一套标准 RAG：用别人已经做好的 Embedding 模型和 Cross-Encoder，先检索再重排。

QASPER 是一套题，里面有论文、问题和参考答案。打分时按题自动操作这个网页：上传这一题对应的论文，填入这一题的问题，先用 A 跑一次，再用 D 跑一次，再用 C 跑一次。三次都拿到网页返回的短答案，再拿去和这道题的参考答案比词重合。

同一道题的三次运行，上传的文件、解析结果、切块、问题、生成模型、提示和短答案要求都相同。唯一变化是模式开关：

- A：整篇正文都送给 DeepSeek。
- D：Jev 逐块判断，只把必要的块送给 DeepSeek。
- C：先用 Embedding 找出较近的块，再用 Cross-Encoder 重排，留下固定数量的块送给 DeepSeek。

测试题有一千多道，不靠人手逐题上传。自动操作走的仍是网页同一套上传、解析和回答接口，所以测到的就是这个网页，而不是另一套程序。

这套 RAG 只在打分时接到同一条回答流程后面，用来对照。用户平时使用网页不需要它。Embedding 模型和 Cross-Encoder 都不自己训练。

## 10. 尚未在立项中锁定

这些留到实验协议，不在本纪要里假装已经选定：

- 切块的 token 窗口和重叠。
- 方案 C 的 Embedding 模型、Reranker 模型，以及召回和送入生成模型的块数。
- 阈值 τ 和证据 token 上限的具体值。
- D 相对 C 的成本是否单列一条及格线。本次先只报告成本。
