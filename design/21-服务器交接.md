这份只交代怎么把改完的代码放到已经买好的服务器上。它不是模块设计。新对话先读这一份，再动服务器。

## 现在到哪了

公网地址是 `http://49.232.168.89:8081`。手机流量已经能打开上传页。

服务器用户是 `ubuntu`。代码在 `/home/ubuntu/jev`，跟踪 GitHub 的 `main`。远端因为直连 GitHub 会超时，已经改成 `https://ghproxy.net/https://github.com/wdwd200/jev.git`。`.env` 只在服务器上，不在仓库里。

应用由 systemd 服务 `jev` 拉起，只听本机 `127.0.0.1:8001`。Caddy 听公网 `8081`，再转到 `8001`。腾讯云防火墙已经放行 TCP `8081`。

同一台机器上的 runtime 使用本机 `8000` 和公网 `8080`。不要停它，也不要改它的端口、目录、密钥或数据库。

## 密钥和密码

密码是一串要输入的字符。写进文件或聊天里就会泄露，服务器被重置密码后也会失效。

现在用的是 SSH 密钥。私钥在这台 Windows 电脑的 `C:\Users\王栋\.ssh\jev_deploy`，公钥已经放进服务器的 `~/.ssh/authorized_keys`。登录时不输入密码。私钥没有进项目，也不能提交到 GitHub。

runtime 使用另一把密钥：`C:\Users\王栋\.ssh\runtime_deploy`。两把不能混用。某一把泄露时，只删掉它在服务器上的那一行公钥。

登录命令：

```bash
ssh -i ~/.ssh/jev_deploy -o IdentitiesOnly=yes ubuntu@49.232.168.89
```

## 什么时候上线

改代码不会自动上线。用户明确说「上线」或「部署」之后才动服务器。

上线前先在本机跑相关测试，再推到 GitHub。服务器上只做这几步：

```bash
cd /home/ubuntu/jev
git pull
.venv/bin/pip install -r requirements.txt
sudo systemctl restart jev
systemctl is-active jev
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8001/
```

本机返回 `200` 后，告诉用户用手机流量打开 `http://49.232.168.89:8081` 检查。不要把 `.env` 拉下来，也不要打印密钥。
