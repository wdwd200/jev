# 30 模块设计：自进化

日期：2026-10-06

前一步：[29-模块-证明.md](29-模块-证明.md)

这一份只定自进化的记录和启用规则。它不调用模型，不改 bge 或 Jev，也不改已经完成的检索、审查和证明。第一版只保存记录，不把经验交给下一次审查。代码还没改。

## 这个模块做什么

自进化读取标成有效的证明，记下哪一种检索说法曾经找对。它不重新判断条款，也不重新计算页码。

租赁合同、劳动合同，以及还没接上 CUAD 标注的商业合同，没有有效证明。它们不产生经验，也不使用经验。

## 一条经验记下什么

一条经验只对应一次有效证明里的一条对照，不把重排和 Jev 混成一条。

| 字段 | 含义 |
| --- | --- |
| 编号 | 这条经验的编号，之后不变 |
| 风险名称 | 8 项默认风险中的哪一项。用户临时增加的风险不进入经验 |
| 检索说法 | 实际送去检索、并且最终被审查采用的那一句 |
| 第二段手段 | 重排或 Jev。整份直送不进入经验 |
| 结果 | 找对或找错。只看条款判断是不是 100 |
| 来源证明 | 哪一条有效证明。同一证明不重复写入 |
| 批次 | 产生这条经验的合同批次 |

证据位置不改变找对或找错。条款判断不是 100，就是找错。证明未完成、无效或没有分数时，不写经验。

## 什么时候能排序

同一风险名称、同一句检索说法、同一种第二段手段，至少有三条来自不同合同的有效经验，才参与排序。不足三条时只保留记录。

排序只看找对次数。次数相同，保持先写入的在前。不按证据位置、费用或延迟重排。

## 两批合同

启用前把没见过的商业合同分成两批。

第一批只产生经验。审查仍使用原问法，不读取经验。

第二批才允许使用。使用方式只有一种：同一风险名称下，审查把排名最高且至少找对一次的说法交给检索。原问法仍保留在审查任务上，不覆盖。经验不决定留下 20 块还是 5 块，也不决定这一轮用重排还是 Jev。

第二批的找错次数多于第一批同一风险的找错次数时，停用这批经验。停用后记录保留，审查回到原问法。不删除经验，也不自动换成下一句。

## 恢复

写入经验是证明完成之后的独立阶段。工作进程按来源证明核对。已经有编号的经验保持原编号。写到一半时，删掉没有编号或不完整的记录，再补缺失项。

第一版即使写出了经验，审查模块也不读取。启用开关另定之前，不能因为记录已经存在就自动使用。
