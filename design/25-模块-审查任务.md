# 25 模块设计：审查任务

日期：2026-10-05

前一步：[24-模块-切块.md](24-模块-切块.md)

这一份只定审查任务。它记录一份合同要核对哪些风险，不执行检索，不判断找到、冲突或缺失，也不调用外部模型。代码还没改。

## 这个模块做什么

切块全部完成后，为这一批合同建立一张风险清单。每一项风险是后面检索和审查的一条独立任务。

网页可以读取清单和进度。工作进程只把已经切完的批次交给这个模块。还有页面没切完时，不建立清单。

## 清单按合同类型换

审查流程不按合同类型拆模块。上传时选定一种类型，这个模块只更换清单。

商业合同不把 CUAD 的 41 类一次性全部放进清单。先固定查这 8 项，顺序也不变：

1. 合同当事人
2. 生效日期和期限
3. 付款金额和付款时间
4. 交付内容
5. 违约责任
6. 赔偿和责任限制
7. 解除和终止
8. 争议解决

房屋租赁的 8 项是：当事人、租赁物、租期、租金和支付、押金、维修责任、解除、违约。

劳动合同的 8 项是：当事人、合同期限、工作内容、工作时间和休息、劳动报酬、社会保险、解除和终止、违约和竞业。

没有 CUAD 这种专家标注的类型只走演示，不报准确率。

用户可以取消其中几项，也可以按原话增加一项。取消和增加只影响这一批，不改变该类型的默认清单。

一项只问一个问题。用户把赔偿和终止写在同一句里时，模块拆开各自建立一项，保留用户的原句。

## 一项记下什么

| 字段 | 含义 |
| --- | --- |
| 编号 | 这一项的编号，之后不变 |
| 所属批次 | 哪一批合同 |
| 风险名称 | 上面的名称，或用户增加的名称 |
| 原问法 | 用户的原话。默认项用风险名称 |
| 检索问法 | 交给下一轮检索的说法。第一轮等于原问法 |
| 状态 | 等待、处理中、完成、失败 |
| 顺序 | 清单里的顺序 |

检索问法以后可以由审查模块更换。这个模块只保存最新一轮要交给检索的说法，不保存每一轮的检索结果。

## 怎么恢复

建立清单是一个阶段。工作进程先把批次写成处理中并提交，再逐项写入。

重新领取时按风险名称和所属批次核对。已经有编号的项保持原编号，不新建重复项。写到一半时，删掉这一批没有编号或不完整的项，再把缺失项补上。

一项检索或审查失败，只把这一项写成失败。其他项继续。全部项都完成或失败后，清单阶段才结束。
