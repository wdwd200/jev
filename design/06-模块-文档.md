# 06 模块设计：文档

日期：2026-09-30
前一步：[05-系统蓝图.md](05-系统蓝图.md)

只设计文档模块。切块规则在 [16-模块-切块.md](16-模块-切块.md)。提问、选文、作答和证明不在这一份里。

2026-09-30 起，这一份是文档模块的现行规则。同日之前写在这里的“一次上传固定成一批、词数近似、图片不识别”不再有效。2026-10-02 起，代码按这一份工作。机器上没有安装 Docling，也没有放 DeepSeek 分词器文件时，解析用 pymupdf，计数用中文字符加英文词。这两项是临时退路，不是另一套规则。

## 这个模块做什么

一次对话里上传的 PDF 全部属于同一批。文档模块保存原文件，用 Docling 抽出文字、表格和图片，数出 token，并判断这一批还能不能继续提问。

同一对话里可以再添加一份 PDF，也可以删除一份。添加和删除都只动这一份。没有对话编号时，才新开一批。

它不决定一块多大，不记录问题，不调用 Jev 或 DeepSeek 作答。Word 和网页以后也要变成同样的文字、表格和图片；这一版只接 PDF。

## 一批是什么

一批是这一次对话里、将要一起阅读的那些 PDF。一份也算一批。它要有编号，因为整篇对照必须能装下这批全文，某一题的选文也必须指向当时那一版。

| 字段 | 含义 |
| --- | --- |
| 编号 | 这一次对话的编号，之后不变 |
| 放入时间 | 这一批建立的时间 |
| 状态 | 处理中、可提问、已拒绝。代码里可提问仍是 `ready`，已拒绝仍是 `rejected` |
| 正文 token 合计 | 还留在这批里、并且抽文成功的文档，文字 token 相加 |
| 窗口上限 | 生成模型上下文的 80%。当前是 80 万 token |
| 拒绝原因 | 只有已拒绝时才有 |

状态只由这个模块改。后面的模块只能读。

处理中只存在于一次上传还没算完的时候。算完就写成可提问或已拒绝。

## 一份文档

| 字段 | 含义 |
| --- | --- |
| 编号 | 这份 PDF 的编号，之后不变 |
| 所属批次 | 它属于哪一次对话 |
| 原文件名 | 上传时的文件名，只用于显示 |
| 原文件 | PDF 本身 |
| 抽文状态 | 已抽出、抽不出 |
| 内容 | Docling 的解析结果。抽不出时为空 |
| token 数 | 文字、表格文本和图注按 DeepSeek 分词器得到的数量。抽不出时为 0 |
| 失败原因 | 只有抽不出时才有 |

某一份失败，不影响同一批里的其他份。

## 技术选型

解析用 Docling。它把表格建成 `TableItem`，把图片建成 `PictureItem`，图注挂在图片上，并保留页码和阅读顺序。这正是后面切块和来源要读的结果。

不继续用现在的 pymupdf 压平。那种做法会把表格变成竖线文本，图片只剩一句说明。Unstructured 能分出文字、表格和图片，但图片和图注是分开的元素。MinerU 对复杂论文更强，但要另跑一套模型服务，不适合和另一个项目放在同一台小机器上。

只借用 Docling 的解析结果，不接入它的问答和检索。

## 抽出的三种内容

解析借用 Docling，不把 Docling 的问答或检索接进来。

页眉和页脚不进入可挑选的正文。它们在每一页重复，留在正文里会让选文反复挑中页码和公司名。页码和文件名改记在每一块的来源上，原 PDF 仍保留，需要时还能看到页眉页脚。

段落内部因排版折行的换行要拼回去。段落之间的分隔保留。不把一整页连成一行，也不把折行当成一块的边界。

- 文字：按阅读顺序的段落。
- 表格：Docling 的 `TableItem`，保存成一整张 Markdown 表格。不压成用竖线串起来的一行。
- 图片：Docling 的 `PictureItem`，保存原图，图注挂在这张图上。柱状图、饼图、折线图如果被转成表格或说明，这段说明跟着图片保存，只用于挑选，不代替原图。

## 添加和删除

添加一份 PDF 时，只解析这一份。新的 token 加上后没有超过 80 万，这份文件加入当前批。超过 80 万，这次添加不生效，原来的文件保持原样。

删除一份 PDF 时，这份文件从当前批去掉，并重算合计。已经答过的题不改：当时选中的文字和图片留在那次选文上。

切块模块负责给这份新文件增加块，或删掉属于这份文件的块。文档模块不自己改块。

## token 怎么数

文字、表格文本和图注用 DeepSeek 公布的分词器计数。中文和英文都走这个分词器，不再把一个英文单词算成一个 token。

这个数只用来判断有没有超过 80 万。以后作答账单上的 token 以接口返回为准，不拿这个数去填。图片本身的 token 等确认生成模型的计法后再记，不先用文字数代替。

换生成模型时，上限和已经记下的 token 都要重算。重算前，这一批不能继续提问。

## 代码做到哪了

同一对话里继续添加和删除 PDF 已经按这一份做了。表格存成 Markdown，图片留下原图，重复出现的页眉页脚不再进入可选正文。

Docling 能导入时优先用它。当前环境没有安装，所以实际走 pymupdf。DeepSeek 分词器文件放好后优先用它。文件没放时，一个汉字算一个 token，一段连续英文算一个 token。账单上的 token 仍然只用接口返回的数。
