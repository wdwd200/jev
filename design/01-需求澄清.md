# 01 需求澄清

日期：2026-09-23
前一步：[立项纪要.md](立项纪要.md)

## 给谁用

所有要基于大量文本提问的人。不是实验人员和普通用户两类。

这些人现在直接把整段文本送给 GPT 或 Claude。这两类模型的调用成本已经很高，少送进去的文本就是在省钱。目前最容易减下来的是文本，而不是图片或其他输入。

网页不面向公众注册，不做账号、权限和组织。第一版是实验台，但使用对象按上面这一类人定义。

## 办成什么

用户拿出一批文本并提出一个问题。网页用 Jev 判断哪些段落必要，只把这些段落和问题交给生成模型，返回答案，并显示这次少送了多少文本、用了多少 token、花了多少钱、用了多久。第一版的文本来源是 PDF。

同一批文件和同一个问题，可以关掉 Jev，把整篇正文交给同一个 DeepSeek。这是对照 A。

打分时，同一套上传、解析和回答流程再接上标准 RAG。它用现成的 Embedding 模型和 Cross-Encoder 选段落，再交给同一个 DeepSeek。这是对照 C。C 不是网页本来就有的功能，也不自己训练。

QASPER 提供论文、问题和参考答案。打分程序按题目调用网页的同一套接口：一道题上传它对应的那一篇，分别用 A、D、C 跑三次，把三次短答案和参考答案比词重合。

## 什么不算

- Jev 不回答用户，不生成解释。
- 不训练 Jev、Embedding 模型或 Cross-Encoder。
- 不更换生成模型，不对比多个生成模型。
- 不把多篇 PDF 一次放入的结果算进 QASPER 分数。网页允许这么用，这套题没有这种考法。
- 不把图和表作为证据的题算进主分数。
- 正文超过模型窗口的 80% 时直接拒绝，不截断后继续比。
- 低置信度不交给生成模型再判一次，只记录比例。

## 第一版包括

- 上传一份或多份 PDF，显示总量是否超过上限。
- 解析正文、按同一规则切块。切块的窗口和重叠仍未定。
- D：Jev 逐块判断，保留概率不低于 τ 的块，并有证据 token 上限。没有块达标时允许空结果；τ 和上限仍未定。
- A：同一批块全部送给生成模型。
- 同一个生成模型、同一套短答案提示、关闭思考模式。
- 返回答案，以及 token、费用、选择耗时和总耗时。
- 打分时可调用的 C：Embedding 召回，Cross-Encoder 重排，留下固定数量的块。用哪个模型、留几块，仍未定。
- 按 QASPER 题目自动调用上述接口，汇总 Answer-F1、Evidence-F1、token、费用和延迟。

## 第一版不包括

- 用户可见的 C 按钮。C 只由打分程序调用。
- 账号、权限、计费产品化和多用户隔离。
- 扫描版 PDF、图片型 PDF 的文字识别。
- 图表问答。
- 多文档提问的专项评测。
- 生产级增量索引和文档更新。

## 这一级仍未定

这些数字留到分模块设计时写死，不在需求里先猜：

- 切块的 token 窗口和重叠。
- Jev 的阈值 τ，以及 D 选中证据的 token 上限。
- C 的 Embedding 模型、Cross-Encoder、召回块数和最终留下的块数。
- 费用按哪一张价格表折算，包括 Jev、Embedding、Reranker 和 DeepSeek。
